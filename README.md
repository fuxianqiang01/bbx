## 三、任务目标与边界

### 已有核心目标

1. **来电与拨号**：连接本机蓝牙电话宝 WebSocket，来电自动查询、等待号码排队、手动录单窗口保护、双击拨号。
2. **流水与订单情况**：今日/本月流水、历史归档、未派订单按时间窗与线路展示。
3. **地图调度**：出发/目的地双图、订单标记防重叠、车辆实时位置、司机分段、改派/报班等。
4. **新单提醒**：v1.9.29 使用独立取数通道，按下单时间发现近 5 分钟新单，不受地图线路和六格时间窗限制。
5. **备注与订单增强**：备注/价格快捷修改、状态提醒、自动发车、订单管理快捷操作。

### 当前本地迁移基线功能：v1.9.29

文件头已保留完整根因与需求原话。核心变化：

- 新单提醒不再借用地图宽池，改走 `flowMapNewOrderPool()`。
- 按下单时间取近 30 分钟数据，用车时间下界为当天、上界为 60 天后。
- 新单解析不过地图线路闸，因此可覆盖日照↔青岛和远期预约单。
- 地图仍按原节奏刷新；提醒条每 30 秒轮询，5 分钟自动顶出。
- 独立通道失败可降级回旧宽池，并通过 `src`/日志辨别。

### 不属本目录的项目

- `bbx-bridge`：H5/抖音桥接服务，不是本油猴项目。
- `bbx-portal`：Node.js + CDP 运营门户，不是本油猴项目。
- 早期 `2026-10-11-09-34-41` 等目录：保留作历史证据，不作为 Codex 开发根目录。

## 四、标准开发流程

1. **明确验收口径**：记录用户原话、问题单/车辆、预期 UI 与数据行为。
2. **核对代码事实**：确认当前版本、实际函数、接口参数和 DOM，不根据旧恢复文档直接改。
3. **先复现再修复**：优先添加行为测试；静态正则只作辅助，不能替代真运行。
4. **最小根因改动**：默认只动渲染；涉及取数或提交时单独说明必要性和影响。
5. **同步版本**：地图脚本升版时同步文件名、`@version`、`var VER`；文件头追加变更，不删除历史。
6. **三层验证**：语法检查 → 专项行为测试 → 全量回归。
7. **真机验收**：用户登录/授权后验证，保存截图、Console、接口或状态证据。
8. **同步交接**：更新本文件和 `AGENTS.md` 的版本、测试、待办，明确未验项。

### 完成定义

- 代码改的是唯一主源码，版本号一致。
- 新专项测试通过，相关旧专项通过，全量结果已解释。
- 真机截图与关键行为断言齐全；涉及提交时核对平台真实结果。
- 无静默失败、无假成功、无未经批准的自动写操作。
- 文档与代码同步，遗留问题有明确下一步。

## 六、浏览器使用流程

### 1. 启动专用调试浏览器

双击：

```text
tools/start-edge-debug.bat
```

它会启动 Edge，参数包括：

- `--remote-debugging-port=9222`
- 独立用户目录 `bbx-platform/.edge-debug`
- 打开 `https://gps51.com` 与 `https://man.bbxhc.com`

不会使用日常 Edge 的配置。不要删除 `.edge-debug` 中仍在使用的会话；也不要把它提交到版本库。

### 2. 登录、安装和刷新

1. 用户手动登录 `man.bbxhc.com`；滑块验证码由用户完成。
2. 在篡改猴安装/更新两个当前文件：
   - `outputs/bbx_auto_call_query_v1.9.0.user.js`
   - `outputs/bbx_flow_orderboard_v1.9.29.user.js`
3. 确认两个脚本均启用，刷新平台页面。
4. 打开“城际调度中心/订单中心”，确认左侧呼叫框、“今日流水”和“订单情况”出现。
5. 如使用实时车位，用户在 gps51 页面完成定位授权；脚本不能代替用户点击授权。

> 旧自动化直写篡改猴存储的脚本含固定 UUID 和旧文件名，本次没有纳入交接工具。默认走篡改猴正常安装/更新，避免误写其它脚本。

### 3. 打开地图

1. 展开“订单情况”。
2. 在对应时间行单击“莒县/日照”等带 `data-flow2cell` 的格子；单击即可，不需要双击。
3. 地图会以同一浏览器窗口中的普通标签页打开。
4. 检查方向、时间窗、未派标记、已指派层、车辆列表、GPS 授权与新单提醒。

### 4. v1.9.29 真机验收清单

| 场景 | 预期 |
|---|---|
| 首轮存在 5 分钟内新单 | 直接显示，不必等下一轮 |
| 日照↔青岛新单 | 能显示，不被莒县线路闸过滤 |
| 用车时间在未来数天 | 只要下单时间在窗口内也能显示 |
| 已派/取消订单 | 不进入新单提醒 |
| 等待 30 秒 | 新数据按平台同档节奏刷新 |
| 超过 5 分钟 | 自动顶出，不依赖下一次请求 |
| 点击“× 清空” | 当前批订单不会因下轮推送立即回填 |
| 独立请求失败 | 有可见日志/来源标记，可降级，不伪造新单 |
| 时间窗浮条 | 不遮挡提醒条 |

### 5. CDP 只读检查与截图

确认 `http://127.0.0.1:9222/json/version` 可访问后，在本目录执行：

```bash
node tools/cdp-eval.js tools/probe-readonly.js man.bbxhc.com
node tools/cdp-shot.js shot-host.png full man.bbxhc.com
```

探针只读取页面 URL、面板和调试 API 是否存在，不提交订单。地图标签页可能是 `about:blank`，截图前要核对 CDP target，不能默认“第一个页面就是地图”。

## 七、真实写操作红线

以下不是普通 UI 测试，必须获得用户当场明确确认：

- 指派/改派、自动派单真写；
- 报班/取消报班、发车；
- 修改备注、价格、订单；
- 取消订单或调用其它会改变平台状态的接口。

当前代码事实：

- `FLOW_MAP_ASSIGN_LIVE=true`：手动指派会真实提交。
- `FLOW_MAP_AUTO_ENABLED=false`：自动派单默认只干跑。
- `__bbxFlowMapAutoOn(true)` 会开启真写，禁止为测试擅自调用。

真机写操作后必须以平台响应和刷新后的真实状态验收，不能只看本地提示。
